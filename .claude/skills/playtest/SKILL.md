# 遊戲驗證

> 老師版已經可以直接用。你要做的是在最下面的「我的測試案例」加入自己的案例。

## 什麼時候用

使用者說「幫我測試遊戲」「確認 bug 修好了沒」時。

## 原則

- **只測試，不修改任何檔案。** 發現問題就回報，不要順手修
- 每個結論都要有證據：畫面上的數字、`npm run check` 的輸出、或截圖
- 遊戲不會存檔：每個案例開始前先按「重新開始」，確保從第 1 天開始

## 測試前準備

1. 確認遊戲已經在跑：`http://localhost:5180` 打得開（沒有就請使用者在 `web-lab` 執行 `npm run dev`）
2. 在 `web-lab` 資料夾執行 `npm run check`，把總結那幾行貼進回報
3. 有瀏覽器 MCP 就用它操作；沒有就把步驟列給使用者手動做

## 畫面上的元素名稱（data-testid）

| 要做的事 | 元素 |
|---|---|
| 切到開店頁 | 上方導覽的「開店」按鈕 |
| 選客人包 | `pack-select` |
| 勾選上架 | `dish-<菜>-toggle`，菜的代號：signature 招牌、chive 韭菜、corn 玉米、soup 酸辣湯、soymilk 豆漿、tea 紅茶 |
| 份數、定價 | `dish-<菜>-qty`、`dish-<菜>-price` |
| 宣傳費 | `promo-0`、`promo-200`、`promo-500` |
| 開始營業 | `open-shop` |
| 略過動畫 | `skip-animation` |
| 打烊報表 | `report-revenue`、`report-stock-cost`、`report-promo`、`report-waste`、`report-waste-fee`、`report-profit`、`report-task`、`report-stars` |
| 進入下一天 | `next-day` |
| 狀態列 | `status-day`、`status-cash`、`status-stars` |
| 客人台詞 | `visit-<第幾位>-line` |

| T2 | 清潔費 | 預設路人；只上架紅茶 30 份、25 元；開始營業 | 只有路人乙會買紅茶（10 杯）；報廢 20 份、清潔費 95 元 |

| T5 | 任務會判定 | 同 T4 | 第 1 天任務顯示「未達成」（有報廢），不是「施工中」 |
| T6 | 客人會說話 | 官方標準關，任意上架後開始營業 | 客人卡片下面有台詞泡泡 |

## 回報格式（每個案例一段）

```text
案例：T1 不能超賣
步驟：1. …  2. …
預期：…
實際：…（附畫面上的數字或截圖）
結果：PASS / FAIL
```

最後附上：`npm run check` 的總結、FAIL 的案例最可能對應到哪一個 `rules/` 檔案。
