# 結果檢討

> 這是**挖空模板**。標 ★ 的地方要你自己填。
> 重點是「看到什麼現象 → 代表什麼問題 → 下一次怎麼改」，讓 AI 像店長一樣檢討。

## 什麼時候用

每跑完一次 `npm run simulate`，要決定下一版策略怎麼改時。

## 試算結果裡有哪些線索

試算工具每天會印出：客人數、收入、備貨、宣傳、報廢（清潔費）、淨利、任務、星等、資金，以及「沒買到的客人」：

| 線索 | 意思 |
|---|---|
| 賣完買不到 | 有人想買，但貨不夠 |
| 嫌太貴 | 價格超過客人剩下的預算 |
| 想吃的沒上架 | 客人想吃的菜今天沒賣 |
| 因為討厭的菜不進門 | 上架了某位客人討厭的菜 |

## 對症下藥表

| 看到的現象 | 代表的問題 | 下一次怎麼改 |
|---|---|---|
| 賣完買不到很多 | 備貨太少 | 那樣菜多備一些（注意合計不能超過 80 份） |
| 報廢 15 份以上 | ★ | ★ |
| 嫌太貴很多 | ★ | ★ |
| 想吃的沒上架很多 | ★ | ★ |
| 因為討厭的菜不進門 | ★ | ★ |
| 星等往下掉 | ★ | ★ |
| ★ 我自己發現的現象： | ★ | ★ |

## 步驟

1. 讀試算結果，逐天找出上表的現象
2. 每一個現象，照對症下藥表提出一個修改
3. **一次最多改 3 個地方**，這樣才知道是哪個修改有效
4. 把修改後的策略存成新的檔案（例如 `plans/v2.json`），不要覆蓋舊的，方便比較

## 回報格式

```text
這一版的結果：最終資金 …、星等 …、報廢 …
發現的問題：
1. 第 N 天：（現象）→（問題）
修改：
1. …
下一版檔名：
```

## 不准做的事

- 不准修改遊戲檔案（`src/` 底下的任何檔案、客人包）
- 只能新增或修改 `web-lab/plans/` 裡的策略檔
