# 助教手冊 ｜ GYOZA WOOD 鍋貼店經營遊戲

> **只給老師與助教，不要發給學生。** 裡面有每個洞的答案。

## 怎麼給提示：分三層，從第 1 層開始

| 層級 | 助教做什麼 | 例子 |
|---|---|---|
| 第 1 層 | 問引導問題，讓學生自己想 | 「你覺得規則書哪一句跟遊戲對不上？」 |
| 第 2 層 | 給方向，不給答案 | 「看看打烊報表的清潔費，報廢 21 份時應該是多少？」 |
| 第 3 層 | 給一個範例，請學生改成自己的版本 | 「你可以參考這條檢查規則，換成你自己的主題。」 |

學生卡關超過 10 分鐘，或第 3 層還是做不出來：讓他下載下一關的起始版（`checkpoint-N` 分支的 zip），先往下走，課後再補。

## 一、五個洞一覽

| 洞 | 檔案 | 學生在遊戲裡會看到的怪事 | 修好後 | `npm run check` | `playtest` 案例 |
|---|---|---|---|---|---|
| 成交規則 | `rules/sales.js` | 備 5 份卻賣出 10 份（超賣），營業收入多算；客人從來不會因為「賣完了」而買不到 | 賣完就買不到，客人說「賣完了」的台詞 | 成交規則 3／6 → 6／6 | T1 |
| 收支規則 | `rules/money.js` | 清潔費永遠 0 元；當日淨利 = 營業收入；大家都很有錢（五天後一萬多） | 淨利扣掉備貨、宣傳、清潔費 | 收支規則 2／8 → 8／8 | T2、T3 |
| 口碑規則 | `rules/reputation.js` | 星等永遠 3 顆，怎麼經營都不動 | 依滿意比例以 0.5 顆升降 | 口碑規則 4／11 → 11／11 | T4 |
| 每日任務規則 | `rules/tasks.js` | 任務永遠顯示「施工中」 | 依五天的任務判定並發獎金 | 每日任務規則 0／10 → 10／10 | T5 |
| 說話規則 | `rules/speech.js` | 客人卡片沒有泡泡 | 依結果顯示對應的台詞 | 說話規則 0／5 → 5／5 | T6 |

另外兩個洞：

- **客人資料**：`customers/my-customers.json` 開課時是 `[]`，選「我的客人包」會出現紅字提示。學生用 `new-customers` skill 產生
- **升級商店**：按鈕點了顯示「尚未開放」。學生最後用 `write-spec` 自己寫規格

### 每個洞的答案（完成版程式在 `solution` 分支的 `web-lab/src/game/rules/`）

| 洞 | 少了什麼 |
|---|---|
| 成交規則 | 少了「庫存 ≤ 0 → `sold_out`」這個檢查（要放在「太貴」之前） |
| 收支規則 | `wasteFee` 沒有照階梯計費；`dailyProfit` 沒有扣掉備貨、宣傳、清潔費 |
| 口碑規則 | 沒有照五條判定計算，也要夾在 1～5 顆之間；沒人進店時不變 |
| 每日任務規則 | 沒有依 `task.id` 判定五種任務 |
| 說話規則 | 沒有回傳 `customer.lines[outcome]` |

### 各洞的三層提示

| 洞 | 第 1 層 | 第 2 層 | 第 3 層 |
|---|---|---|---|
| 成交規則 | 「只備 5 份招牌鍋貼，報表說賣了幾份？合理嗎？」 | 「規則書說買得到要符合哪三個條件？程式檢查了幾個？」 | 「打開 `sales.js`，對照三個條件逐一找」 |
| 收支規則 | 「五天後你有多少錢？跟同學比合理嗎？」 | 「報廢 21 份，規則書的清潔費應該是多少？畫面寫多少？」 | 「規則書的淨利公式有四項，`money.js` 用了幾項？」 |
| 口碑規則 | 「你的星等有變過嗎？」 | 「規則書說什麼情況星等會變？」 | 「把規則書那張五條判定的表格整張貼給 AI，請它照表實作」 |
| 每日任務規則 | 「任務欄寫什麼？」 | 「五天的任務分別要怎麼判斷達成？」 | 「`tasks.js` 開頭的註解列出了 report 有哪些欄位可以用」 |
| 說話規則 | 「客人有說話嗎？」 | 「客人包裡有台詞嗎？台詞是用哪個欄位存的？」 | 「`pickLine` 拿到了 customer 和 outcome，怎麼從 customer 找到對應的那句？」 |

**最常見的錯**：AI 為了讓 `npm run check` 通過，去改 `scripts/check-rules.mjs` 或把答案寫死。看到 `git diff` 動到 `rules/` 以外的檔案，就請學生用 `review-diff` skill 檢查並還原。

## 二、Skill S1「客人資料製作」：自訂檢查規則的提示

學生要在模板加一條自己的檢查規則。想不出來時，先問三個引導問題：

1. 什麼樣的客人會讓遊戲**壞掉**？（對應類型 1、2）
2. 什麼樣的客人會讓遊戲**變無聊**？（對應類型 3）
3. 什麼樣的客人**不符合我想要的感覺**？（對應類型 4）

### 四種類型的範例（第 3 層才給，請學生改寫成自己的）

**類型 1：避免邏輯矛盾**

| 檢查規則 | 要擋掉什麼 |
|---|---|
| 同一位客人的 wants 和 hates 不能是同一樣 | 「最愛韭菜，但討厭韭菜」 |
| 預算至少要買得起 wants 裡最便宜的那一樣（以建議售價計算） | 永遠買不起任何東西的客人 |
| intro 和 wants 不能互相矛盾（介紹寫吃素，wants 就不能有招牌鍋貼） | 自稱吃素卻點豬肉 |

**類型 2：避免台詞出錯**

| 檢查規則 | 要擋掉什麼 |
|---|---|
| bought 台詞不能提到特定菜名 | 買的是紅茶，台詞卻在講鍋貼 |
| not_on_menu 和 sold_out 兩句不能一樣 | 玩家看不出客人到底為什麼沒買 |
| 台詞不能有髒話、歧視或真實人名 | 不適合公開展示的內容 |

**類型 3：讓遊戲保持公平、好玩**

| 檢查規則 | 要擋掉什麼 |
|---|---|
| 同一天出現的客人，wants 不能全部集中在同一樣菜 | 只備一種菜就能通關 |
| 五天裡每一天都至少要有一種客人出現 | 某一天完全沒有客人 |
| 整包客人至少要有一位有 hates | 每個人都什麼都吃，口味策略沒意義 |

**類型 4：符合自己定的主題**

| 檢查規則 | 要擋掉什麼 |
|---|---|
| 每位客人的 intro 都要跟主題有關 | 主題是「期末考週」，卻出現退休阿伯 |
| 名字不能和官方客人包重複 | 跟別人的客人撞名 |

**助教驗收問兩題**：「你自己加的檢查規則是哪一條？它擋掉了什麼？」答不出來就不算過關。

### 課堂上的「故意漏洞」

`bought` 台詞常常寫成「有鍋貼吃真好」，但客人可能只買到紅茶（第一順位沒上架、第二順位買到了）。學生玩的時候會看到「買紅茶卻說鍋貼台詞」——這是讓他們回頭補類型 2 規則的好時機。

## 三、Skill S2「遊戲驗證」：我的測試案例

學生要加至少 1 個案例。想不出來時的範例：

| 案例 | 操作 | 預期 |
|---|---|---|
| 宣傳有效 | 官方標準關，宣傳選 500，其他同 T4 | 第 1 天進店人數比不宣傳時多（約 1.45 倍） |
| 討厭的菜會趕客 | 官方標準關，上架韭菜鍋貼 | 「怕韭菜的 OL」卡片顯示沒進門 |
| 產能上限 | 任一菜份數填 81 | 出現「超過每日產能 80 份」，開始營業按鈕不能按 |
| 不能透支 | 第 1 天備貨總成本超過 2,000 元 | 出現「超過現有資金」的錯誤 |

T1～T6 的實際數字（完成版）：T1 營業收入 350 元；T2 報廢 20 份、清潔費 95 元；T3 收入 250、備貨 240、淨利 −85；T4 星等 3 → 4；T5 未達成；T6 有泡泡。掉漆版：T1 收入 700、T2 清潔費 0、T3 淨利 250、T4 星等不變、T5 施工中、T6 沒有泡泡。

## 四、MCP（chrome-devtools）

### 設定

1. 專案根目錄的 `.mcp.json` 已經寫好，用 Claude Code 打開專案資料夾時會詢問是否啟用，選啟用
2. 在 Claude Code 輸入 `/mcp`，應該看到 `chrome-devtools`
3. 最小測試：先 `npm run dev`，再對 Claude 說「請打開 http://localhost:5180 並回報頁面標題」，應回報「GYOZA WOOD｜鍋貼店經營遊戲」

### 權限三問的參考答案

| 問題 | chrome-devtools MCP |
|---|---|
| 它能讀到什麼？ | 它打開的網頁畫面、console 訊息、網路請求 |
| 它能不能寫入？ | 能在網頁上點擊、輸入；不會改專案檔案 |
| 會不會碰到正式資料或 token？ | 這門課只開 localhost 的遊戲，沒有正式資料；但它能開任何網址，所以不要叫它登入私人帳號 |

### 常見失敗

| 狀況 | 處理 |
|---|---|
| `/mcp` 看不到 chrome-devtools | 確認是在專案根目錄打開 Claude Code；重開一次並選啟用 |
| 第一次很久沒反應 | `npx` 正在下載，等 1～2 分鐘 |
| 打不開 localhost:5180 | 遊戲沒在跑：另開終端機 `cd web-lab && npm run dev` |
| 找不到 Chrome | 電腦要先安裝 Google Chrome |

**保底**：MCP 裝不起來的學生，照 `playtest` 案例手動操作並截圖，遊戲任務照樣完成；但「MCP 實作」這一項要看老師示範或課後補做，不能用手動操作代替。

### 學生想不出「自己的測試指令」時

- 「打開遊戲，切到開店頁，告訴我第 1 天的預告寫什麼」
- 「把招牌鍋貼份數填 81，告訴我畫面出現什麼錯誤」
- 「截一張開店頁的圖給我」

## 五、Agent A1「測試員」

### 模板各欄的參考答案

| 欄位 | 參考答案 |
|---|---|
| 職責 | 照 playtest 的案例操作遊戲，回報每個案例有沒有通過，並附上證據 |
| 該勾的 | `playtest` skill、瀏覽器 MCP、`npm run check` |
| 不該勾的 | `change-feature`（測試員不改程式）、`new-customers`（跟測試無關） |
| 多一條禁止事項 | 「不准自己決定 PASS，沒有證據就寫 FAIL」或「不准跳過任何案例」 |
| 多一個回報欄位 | 「截圖檔名」、「可能對應的 rules 檔案」、「重現需要幾步」 |

### 驗收

1. 學生說「請用 tester agent 測試遊戲」，Agent 跑完並回報
2. **跑完後學生執行 `git status`，必須沒有任何檔案被改**——這是確認 Agent 遵守「不准改檔」的證據
3. 學生要說得出：Agent 負責做事、Skill 規定流程、MCP 讓它能操作瀏覽器

學生想不出職責或禁止事項時，先問：「如果你是店長，請一個工讀生來幫你試吃，你會交代他什麼？不准他做什麼？」

## 六、平衡參考（官方標準關）

| 玩法 | 五天後資金 |
|---|---|
| 全部備招牌 | 505 |
| 四樣平均、原價 | 2,626 |
| 低價衝量 | 3,637 |
| 認真玩家，每天宣傳 500 | 7,368 |
| 認真玩家，不宣傳 | 8,129 |
| 認真玩家，每天宣傳 200 | 8,605 |
| 認真玩家，看情況宣傳 | 8,764 |
| 程式搜尋的最佳解 | 約 12,800 |

最佳解的思路：前兩天低價衝口碑（星等上去，後幾天客人變多），後幾天漲價收割；宣傳 200 大多數日子划算，500 只在客人特別多的日子划算。適合結業時公布當討論題。

掉漆版因為不扣成本，資金會到一萬多到兩萬，這是正常的，也是學生第一個會注意到的怪事。
