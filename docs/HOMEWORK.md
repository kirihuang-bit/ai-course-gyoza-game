# 回家作業與課後延伸（簡報製作用）

> 這份文件給**寫課堂簡報的人或 AI**（例如 ChatGPT）讀，說明 GYOZA WOOD 課程裡哪些是**學生回家自己做**的，哪些在課堂完成。
> 請搭配 `docs/RULES.md`（遊戲規則書）和 `docs/INTENTIONAL-BUGS.md`（刻意留給學生的 bug 清單）一起讀。
> 最後更新：2026-10-02

---

## 0. 給寫簡報的 AI：先讀這段

- 課程 12 小時，分 3 天，每天 4 小時。對象是完全沒有程式基礎的上班族、法律系與土木系學生。
- 課程重點是學會 **Skill、MCP、AI Agent**，遊戲只是讓課程好玩的外殼。
- **回家作業只有一份：升級商店。** 其他課後活動都是選做、不計分的延伸。
- **課堂上沒做完的東西不用回家補。** 進度落後的學生，隔天上課下載「換關版本」（GitHub 分支）接著做就好。
- 介紹作業時，請強調它練的是**課程結束後的真實情境**：沒有老師準備好的半成品、只有一句話的需求，要自己從規格開始做。

## 2. 回家作業：升級商店（必做）

### 2.1 起點

- 遊戲開店頁上方有一顆「**升級商店**」按鈕，課堂上按下去只會顯示「升級商店尚未開放」。
- 作業需求只有一句話：**「店裡要有升級商店。」**
- 從**自己課堂做完的專案**開始；課堂沒做完的人，從 `checkpoint-4` 分支開始（所有規則 bug 都已修好）。

### 2.2 三選一的方向

為了讓新手做得完，升級商店**只做一樣商品**，從下面三個方向選一個。價格是建議值，學生可以在規格書裡自己調，但要寫出理由。

| 方向 | 商品 | 效果 | 建議價格 | 會碰到的既有規則 |
|---|---|---|---|---|
| A | 新鍋子 | 每天產能從 80 份變 90 份 | 800 元 | 每天要做的決定（產能上限） |
| B | 招牌燈 | 每天來客數 +10% | 600 元 | 來客數與口碑星等 |
| C | 冰箱 | 每天的報廢量打 8 折（四捨五入）後再算清潔費 | 500 元 | 收支與廚餘清潔費 |

共同規則（三個方向都一樣）：

- 只能在**某一天開店前**購買，買了之後**從當天到第 5 天都有效**。
- 每一場最多買一次，錢不夠不能買。
- 跟遊戲其他部分一樣**不存檔**：重新整理就回到第 1 天、沒買過的狀態。

### 2.3 要做的步驟

| 步驟 | 做什麼 | 用到的工具 |
|---|---|---|
| 1 | 開一個新分支，例如 `homework/upgrade-shop` | git（第 1 天教過） |
| 2 | 讓 AI 用 `write-spec` Skill 把「店裡要有升級商店」寫成規格書。AI 會先問問題（一次最多 3 個），學生回答後，規格書存到 `docs/specs/upgrade-shop.md` | `write-spec` Skill |
| 3 | 自己讀過規格書，確認「規則都寫成數字」「驗收案例至少 3 個」 | — |
| 4 | 讓 AI 照規格書，用 `change-feature` Skill 實作：先看計畫、核准後才動手 | `change-feature` Skill |
| 5 | 驗收：規格書裡自己寫的驗收案例逐一測試，可以讓測試員 Agent 用瀏覽器 MCP 幫忙測；再跑 `npm run check` 確認原本 72 條全部通過 | 測試員 Agent、瀏覽器 MCP、`npm run check` |
| 6 | commit、推上 GitHub、開 PR（Pull Request） | git、GitHub（第 1 天教過） |
| 7 | 把 PR 連結交給老師 | — |

### 2.4 繳交與驗收

| 項目 | 內容 |
|---|---|
| 繳交內容 | GitHub 上的 PR 連結 |
| 期限 | 由老師在課堂上公布 |
| 驗收標準 1 | 規格書 `docs/specs/upgrade-shop.md` 存在，格式符合 `write-spec` 的要求（一句話說明、玩家操作、用數字寫的規則、不做什麼、影響的既有規則、至少 3 個驗收案例、要改的檔案） |
| 驗收標準 2 | 規格書裡的驗收案例都能通過 |
| 驗收標準 3 | `npm run check` 原本的 72 條全部通過，代表**沒有把原本的規則改壞** |
| 不能做的事 | 修改 `web-lab/scripts/check-rules.mjs` 或 `simulate.mjs` 來讓測試通過；加任何存檔或連網功能 |

### 2.5 跟課堂規則不一樣的地方

課堂上 `AGENTS.md` 禁止修改「老師檔」（例如 `engine.js`、`GameShop.jsx`、`config.js`）。但升級商店一定要改到這些檔案，所以：

- **在自己的作業分支上**，可以修改規格書「要新增或修改的檔案」裡列出的檔案。
- 驗收工具 `check-rules.mjs`、`simulate.mjs` 仍然不能改。
- `AGENTS.md` 已經寫了這條例外，AI 會照著做。

### 2.6 教學重點（簡報可以強調）

- 這是課程裡**唯一沒有半成品**的任務，練的是以後在工作上自己用 AI 開發的完整流程：**一句話需求 → 規格書 → 分支 → 實作 → 驗收 → PR**。
- 規格書是重點。範圍越小越好，第一版只做一件事；每條規則都要寫得出「輸入什麼 → 應該看到什麼」。
- 驗收不能只靠 AI 說「做好了」，要有證據：自己寫的驗收案例、`npm run check`、瀏覽器實際操作。

## 3. 課後延伸 1：出題關（選做、不計分）

| 項目 | 內容 |
|---|---|
| 做什麼 | 用 `question-setter` Agent 設計一包「刁鑽、但完全合乎規則」的客人包，讓同學的店虧錢 |
| 什麼時候做 | 課堂上提早完成的人可以當場做；其他人可以帶回家做 |
| 怎麼玩 | 把客人包的內容（`my-customers.json` 的文字）貼到群組；同學在遊戲開店頁按「匯入客人包」貼上就能挑戰。匯入的客人只在那一場有效，重新整理就消失，不會改到任何檔案 |
| 規則 | 格式要通過檢查（預算 30～150 元、想吃 1～2 樣、討厭最多 1 樣、每種客人 1～12 位、單日合計最多 50 位）；不准出無解題（每一天都至少要有一種上架組合能讓店不虧錢） |
| 出題技巧（Agent 裡有寫） | 預算卡在常見定價下面（例如 69 元）；讓兩種客人的喜好互相衝突；讓特定日子的客人集中在某一樣菜 |
| 練到什麼 | 再用一次 Agent；Agent 呼叫 Skill（`new-customers`）、用 MCP 試玩、自己檢查有沒有違規 |

## 4. 課後延伸 2：新營業事件（選做、不計分）

| 項目 | 內容 |

| 練到什麼 | 寫出「AI 只能產生草案、不能直接改正式檔案」的 Skill，練習替 AI 設下界線 |

## 5. 建議（不算作業）：再跑一次 AI 店長

第 3 天公布老師示範策略（最終資金 12,809 元）時，會講到兩條心得：

1. 前兩天用比較低的價格讓客人滿意、衝高星等，星等高了客人變多，後面幾天再漲價。
2. 宣傳 200 元大部分日子都划算，500 元只有客人特別多的日子才值得。

可以建議學生回家把這兩條加進自己的定價心法 `pricing-rules`，再叫 AI 店長跑一次，看分數有沒有進步。**不用交，也不計分。**
